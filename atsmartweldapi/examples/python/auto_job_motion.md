# 从当前 TCP 创建工程并下发自动作业：Y+200 → X+200 → Z+200

脚本：[`auto_job_motion.py`](auto_job_motion.py)。适用当前已配置的 xCore / CR7 / 192.168.1.160。
使用原生 Python SDK，通过 ROS 2 连接服务端；不是 SSH，也不使用 9090。

## 当前功能与边界

按现场要求，默认生成 **三条直线焊缝 `node_type=0`**，不再用三个空跑点替代焊缝：

- 每条焊缝包含起点、终点，后一条起点接前一条终点；顺序为 Y+200、X+200、Z+200。
- 每条焊缝关联传入的工艺 ID、工艺类别，工件和工程关联指定 TCP。
- 焊缝运动参数应由关联工艺和服务端规划决定，不使用 `dry_run_path_params`。
  `--speed` 的历史输入上限检查**不能证明焊缝规划速度已限速**。
- `--preview` 查询当前起点、核对工艺关联并保存焊缝任务，不写库、不下发、不启动。
- **当前 `--execute` 在连接、写库之前直接拒绝**。此前只针对空跑点的“恰好三段且无
  起收弧标志”校验不适用于焊缝；焊缝禁焊门控、工艺速度、接近/退枪路径及预规划校验
  尚未完成适配。不能删除检查后直接启动，更不能将焊缝类型视为禁焊保证。

“不实际起弧”不等于“使用空跑点”。之前的类型选择没有验证焊缝执行链路。
任务生成已改为焊缝。通用 CLI 的执行入口仍拦截；2026-10-23 另用绑定工程 UID/Action UUID 的一次性脚本进行了下述现场测试。
历史空跑执行代码保留用于已有回归测试，不从当前 CLI 自动回退到空跑点。

自带路径的非扫描工件使用 `workpiece_db_id=0`，表示不引用工件库模板；它不是
创建工程返回的工件 `id`。不能沿用示例模板的 `-1`：当前服务端只在扫描任务中
跳过负 ID，非扫描任务会查询工件库并可能返回 `Workpiece id does not exist.`。

## 坐标系必须先确认

当前 xCore 适配 `getCurPos()` 取 `endInRef`，xyz 转为 mm，姿态原样保留（rad）；
任务点位转换也原样保留六个数。**这不自动证明当前参考系就是世界/基座系**。
本脚本不实现坐标变换：只有现场确认当前参考系、世界系和任务基座系对齐，且指定 TCP
就是当前实际工具时，才使用 `--confirm-frame-and-tcp`。不满足时不要加这个参数运行。
服务端准备任务可能加载 TCP，因此启动前重新读取位置，漂移超过1 mm或0.001 rad就拒绝启动。
数据库当前 TCP ID 检查不是物理标定或控制器实际工具一致性认证。

## 先预览（只有查询和本地文件，不写库、不发运动）

在当前 Ubuntu 虚拟机已配置 ROS 的终端运行。下面的 `TCP_ID`、`PROCESS_ID`
需要改成现场真实且相互匹配的 ID；不要照搬旧测试工程/工艺 ID。

```bash
cd /path/to/ros_workspace
source verification/python-sdk-manual/setup_local_sdk.bash

# 必须填写现场确认的数字；此处故意不给可能错误的默认 ID。
TCP_ID=填写当前TCP_ID
PROCESS_ID=填写已审核工艺ID

python3 atweldsystemapi/examples/python/auto_job_motion.py \
  --preview --tcp-id "$TCP_ID" --process-id "$PROCESS_ID" \
  --run-id preview_001 --output verification/motion_preview_001 \
  --confirm-frame-and-tcp
```

输出 `origin.json` 和 `generated-task.json`。预览时机器人必须已经连接，否则停止。
若当前位置为 `(x0,y0,z0)`，目标依次为：

|段|目标位置（mm）|
|---|---|
|Y+200|(x0, y0+200, z0)|
|X+200|(x0+200, y0+200, z0)|
|Z+200|(x0+200, y0+200, z0+200)|

总路程600 mm，不是离起点只移动200 mm。脚本不提供碰撞、可达性或关节余量认证。

## 真实执行暂未开放

不要把预览 JSON 直接交给其他下发工具绕过门槛。此次已知的奇异点路径必须重新审核；
还需适配真实焊缝预规划和禁焊检查，才能恢复执行入口。下方现场记录是此前
**空跑节点版本**的历史证据，不是当前焊缝版本已经跑通的证明。

## 异常处理与版本限制

- 没有服务、未知状态、工艺关联错误、TCP错误、无预规划、预规划新增过渡段或出现起弧标志：停止后续请求。
- 部分部署没有 `get_workpiece_plan_path` 或完整 `route_plan_result`；脚本会停止，不能删掉校验强行启动。
- 下发 `direct_run=0` 也可能清理数据、准备设备、加载配置；不等于纯离线校验。
- UID 回读不是锁。其他客户端不得同时编辑/切换任务或修改 TCP、工艺。
- 超时、异常、Ctrl+C、Action cancel 或 SDK close 不保证设备停机。本脚本不自动重发、
  删除工程、恢复设备配置、往返或下电；紧急情况执行现场安全流程。
- 如果任务受理后校验失败，任务可能仍处于等待状态，保留证据并检查，不能直接重跑。

对已排查的 `1011008 / Workpiece id does not exist.` 准备阶段错误，修正输入后可显式指定
`--recover-failed-uid 原失败任务UID`。此入口只接受同 UID、同错误、纯空跑非扫描任务，
并核对新鲜系统状态为空闲、机器人连接且静止、前后任务状态不变。默认仍拒绝失败反馈；
不接受其他错误或未知状态，不自动停止、销毁或循环重试。服务端仍独立执行任务准入检查。
